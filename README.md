# تقارير الحضور لأجهزة بصمة ZKTeco

برنامج يتصل بجهاز البصمة مباشرة. يسحب التقارير، ويتحكم بالجهاز، ويدير الموظفين، بدون برنامج ZKTeco Attendance Management.
مكتوب بلغة **Go** بدون أي مكتبة خارجية، ويشتغل على ويندوز ولينكس وماك وأندرويد، وكتطبيق على الآيفون والآيباد.

## تطبيق الآيفون والآيباد
ينبني تلقائياً على GitHub Actions بعد كل تحديث. نزّل ملف `ZKAttendance.ipa` من صفحة **Actions**، من آخر تشغيل ناجح، بقسم Artifacts.

التنصيب (Sideload):
- **Sideloadly** أو **AltStore**: سجّل بحساب Apple ID. بالحساب المجاني التطبيق يحتاج تجديد كل 7 أيام.
- **TrollStore**: إذا جهازك يدعمه، التنصيب دائمي.

أول مرة تتصل بجهاز البصمة، iOS يسألك عن **الشبكة المحلية**: اضغط **سماح**.
ملفات البرنامج (النسخ الاحتياطية وبيانات الموظفين) تلگاها بتطبيق **الملفات**: على الآيفون ← الحضور.

## الحاسبة والسيرفر
```
./build.sh             # يبني لكل الأنظمة بمجلد dist
./tools/package.sh     # يجهز ملفات التوزيع: ويندوز ولينكس وماك وأندرويد
git tag v2.6.0 && git push origin v2.6.0   # يبني تطبيق الآيفون والآيباد على GitHub (فرع ci-results)
```

## الدخول والصلاحيات
البرنامج دائماً يطلب اسم مستخدم وكلمة سر، وكل مستخدم إله صلاحية وحدة:

| الصلاحية | شيگدر يسوي |
|---|---|
| مشاهد | يسحب البيانات، يشوف التقارير ويصدّرها ويطبعها، ويقرا معلومات الجهاز ووقته |
| مشرف | كل شي بالمشاهد، ويا أوامر الجهاز العادية (مزامنة الوقت، فتح الباب، الصوت، رسالة الشاشة، إيقاف وتفعيل البصمة، إعادة التشغيل) وتعديل أسماء الموظفين وبطاقاتهم وبياناتهم الإضافية |
| مدير (صلاحية مطلقة) | كل شي، ويا الأوامر الخطرة والمخفية: الإطفاء، مسح سجل البصمات، مسح كل بيانات الجهاز، إضافة وحذف موظفين بالجهاز، صلاحياتهم وأرقامهم السرية، حذف بصمات الأصابع، إلغاء مدراء الجهاز، مسح سجل عمليات الجهاز، تصفير إعدادات الأبواب، قراءة وكتابة إعدادات الجهاز المخفية، ضبط وقت محدد، استرجاع الموظفين من نسخة، البصمات اليدوية، وإدارة المستخدمين وسجل العمليات |

- الصلاحية يتأكد منها الخادم بكل طلب، مو بس الصفحة تخفي الأزرار.
- كل أوامر الجهاز من مكتبة pyzk (وأرقامها نفسها بمكتبة node-zklib). كل أمر يمسح أو يغير شي يحفظ نسخة بمجلد `backups` قبله، و"مسح كل البيانات" ما يتنفذ إلا إذا انكتبت عبارة «امسح الكل».
- سجل العمليات (`data/audit.log`): منو سوّى شنو ومتى ومن أي جهاز، بدون أي كلمة سر أو رقم سري.
- البصمات اليدوية (لموظف نسى يبصم أو كان بواجب): المدير يضيفها من البرنامج، وتنحفظ بـ `data/manual-punches.json` مو بالجهاز (ما أكو أمر يكتب بسجل الجهاز). تدخل بالتقارير مكتوب يمها «يدوية» ويا السبب واسم اللي ضافها.
- أول تشغيل على نفس الحاسبة: المتصفح يطلب إنشاء حساب المدير. بوضع الشبكة يطلبه بنافذة الأوامر، أو بـ `--password`.
- كلمة السر من النسخ السابقة تصير كلمة سر حساب `admin`.
- نسيت كلمة سر المدير: `zk-attendance --reset-admin` (يشتغل حتى والبرنامج شغال).

## تصفية الإجازات والزمنيات
تبويب «التصفية والإجازات»: المدير يرفع تقرير الإجازات من نظام الإجازات (Excel ‎.xlsx‎ أو CSV)، والبرنامج يطابقه ويا الحضور:
- **الربط برقم البصمة فقط** (الأسماء ممكن تختلف بالكتابة). يتعرّف على العمود من عنوانه: «رقم البصمة» أو «رقم الموظف» أو «رقم الطلب».
- **رقم بخانة الأيام = إجازة**: تبرّر غياب كل يوم دوام بمدى «من–إلى».
- **رقم بخانة الساعات = زمنية**: تبرّر نقص بصمة الصباح أو المساء بذاك اليوم. (خيار: تغطي كمان التأخير والخروج المبكر ضمن ساعاتها.)
- **بس «معتمد» يبرّر**؛ «بانتظار…» ينعرض «بانتظار الموافقة»، و«مسحوب/مرفوض» ينهمل.
- البصمة الوحدة باليوم: قبل منتصف الدوام = دخول، وبعده = خروج.
- النتيجة: لكل غياب أو نقص بصمة — مبرّر بإجازة / مبرّر بزمنية / بانتظار الموافقة / غير مبرّر، ويا «إجازة مع حضور». وأعمدة بالملخص، وحالة بالتقرير اليومي، وتصدير Excel.
- الأرقام اللي بالتقرير وما موجودة بالجهاز تنعرض بقائمة. رفع تقرير جديد يحل محل الطلبات المحفوظة بنفس فترته وتبقى الفترات الأقدم. البيانات بـ `data/leaves.json`.

## الأمان
- الصلاحية تُفحص في الخادم بكل طلب، فلا يكفي إخفاء الأزرار. المشاهد والمشرف لا يقدرون يتجاوزون حدودهم حتى لو نادوا الـ API مباشرة.
- كلمات السر: PBKDF2-SHA256 (120000 دورة) + ملح عشوائي، ومقارنة بزمن ثابت. الجلسات: رمز عشوائي من الخادم (يُخزَّن مجزّأً)، HttpOnly و SameSite=Lax، وتبطل عند تغيير كلمة السر أو الخروج. حجب بعد 10 محاولات دخول فاشلة خلال 10 دقائق. طلبات التعديل من أصل آخر مرفوضة (حماية CSRF).
- سجل التدقيق مربوط بسلسلة بصمة (hash chain): أي تعديل أو حذف أو إعادة ترتيب لقيد يُكتشف بالأمر `zk-attendance --verify-audit`. للحماية من قصّ آخر السجل أو إعادة بنائه بالكامل من يملك صلاحية الملف، استخدم `--audit-mirror <ملف>` لمجلد "إلحاق فقط" أو جهاز آخر.
- ملفات البيانات تُكتب بأذونات `0600` (محصورة بمالك العملية). شغّل الخدمة بمستخدم نظام مخصّص محدود الصلاحيات.
- بوضع الشبكة، فعّل التشفير: `--tls-cert`/`--tls-key` (أو ضع البرنامج خلف وكيل HTTPS أو VPN). بدونه تمر كلمات السر والجلسة بالشبكة نصاً صريحاً.
- **فحص أمان الجهاز:** بطاقة «فحص أمان الجهاز» (للمشرف فما فوق) تسوي فحص قراءة‑فقط لجهاز البصمة: هل عليه كلمة سر اتصال، هل عليه مدير، ومخاطر الشبكة والبرنامج الثابت — ويطلّع نقاط بمستوى خطورتها ومعالجتها. (بيانات الجهاز قابلة للتعديل عبر الشبكة لمن يتصل بيه، ولهذا يهمّ وجود كلمة سر الاتصال ومدير على الجهاز.)
- **ضبط كلمة سر اتصال الجهاز:** إذا الفحص لگى الجهاز مفتوح (بلا Comm Key)، المدير يقدر يضبط كلمة سر اتصال من البرنامج (قسم أوامر المدير ← «كلمة سر اتصال الجهاز»). البرنامج يكتبها بالجهاز، يتحقق إنها انطبقت فعلاً، ويحفظها حتى يكمل الاتصال. إذا جهازك ما يقبل ضبطها عبر الشبكة، يرشدك تسويها من قائمة الجهاز. **ولتغييرها لاحقاً** فعّل «بدّل كلمة السر الموجودة» (يستخدم الحالية ويبدّلها)، أو خليها 0 ويا «بدّل» لتعطيلها. هذي العملية **للمدير فقط**.
- تقرير الفحص الأمني الكامل للبرنامج انسلّم منفصل (ما ينحفظ بالمستودع لأنه يوصف نقاط الضعف).
